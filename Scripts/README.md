# Instruction of Scripts
Python scripts for preparing the training data of CLOVERS heuristic models, training the models, and evaluating gene-prediction accuracy and speed. These scripts belong to the **developer tools** and are not related to the use of the final built program that is released.

The numbered filenames indicate the typical order of the pipeline:
`01.GC_Partition.py` → `02.Train.py` → `03.Eval.py` / `04.Test_Speed.py`.
`05.Neg_Ctrl.py` is an auxiliary negative-control generator (see section 05):
it builds decoy-spiked genomes for false-positive testing and does not consume
the output of the previous scripts.

## 01. Partitioning Datasets by GC Content
`01.GC_Partition.py` partitions the Positive/Negative sequence datasets into GC-content bins, so that balanced training subsets can be sampled per GC range.

```bash
python 01.GC_Partition.py --input data_root --output binned_root # [other options]
```

### Input
The input root directory must contain two subdirectories, `Positive/` and `Negative/`, holding FASTA files (`.fna`, `.fasta`, `.fa`).

| Option      | Description |
|-------------|-------------|
| `--input`   | Input root directory containing the Positive and Negative subdirectories (required) |
| `--output`  | Output root directory for the GC-binned FASTA files (required) |
| `--min-gc`  | Lower GC-content bound in percent, inclusive (default: 20) |
| `--max-gc`  | Upper GC-content bound in percent, exclusive (default: 80) |
| `--step`    | GC bin width in percentage points (default: 1) |
| `--no-plot` | Do not generate GC-distribution plots |

### Output
- `Positive/Positive_<lo>_<hi>.fasta`, `Negative/Negative_<lo>_<hi>.fasta` — one FASTA file per GC bin (e.g. `Positive_25_26.fasta`).
- `GC_partition_report.txt` — plain-text summary of the per-bin sequence counts.
- `Positive_GC_distribution.png`, `Negative_GC_distribution.png` — bar charts of the GC distributions (requires `matplotlib`, skipped if not installed).
- `GC_Partition.log` — run log.

## 02. Training Heuristic Models
Use the training data generated by the *ab initio* ORF Labeler (src/Labeler.cpp) to train the heuristic models for small, draft and meta-genomes:

```bash
python 02.Train.py -p positive.fasta -n negative.fasta -o model.pth # [other options]
```

Requires the `Zcurve` Cython extension to be built first (see the appendix below); sequences are encoded into 189-dimensional Z-curve features and used to train a single-hidden-layer MLP (189 → 100 → 1) with PyTorch.

### Input
| Option              | Description |
|---------------------|-------------|
| `-p, --pos_file`    | Path to FASTA file of CDS (positive) sequences (required) |
| `-n, --neg_file`    | Path to FASTA file of ncORF (negative) sequences (required) |
| `-o, --output`      | Path to save the trained model (default: `model.pth`) |
| `-e, --num_epochs`  | Number of training epochs (default: 20) |
| `-l, --learning_rate` | Learning rate for the Adam optimizer (default: 0.001) |
| `-t, --threshold`   | Threshold for binary classification (default: 0.5) |
| `-s, --test_size`   | Proportion of the dataset used for validation (default: 0.1) |
| `-q, --quiet`       | Suppress verbose output |

### Output
The output file `model.pth` (a `joblib` dump) will contain the trained model.
```json
model = {
    "state_dict": model_state,  # State dictionary of the trained model (torch.nn.Module.state_dict())
    "scaler": scaler,           # StandardScaler object for feature scaling (sklearn.preprocessing.StandardScaler)
    "threshold": threshold,     # Threshold value for classification (float)
}
```
The model state with the best validation F1 across epochs is kept.

## 03. Evaluating Gene Finders
`03.Eval.py` compares predicted CDS features (from a group of GFF files) with reference CDS features.

An ORF is considered a **true positive** if it shares the same host sequence, strand, and has either a matching 5′ end or 3′ end (start/end positions depending on strand). Each reference ORF can be matched at most once.
The script processes all `.gff` files in a prediction directory and matches them against corresponding files in a truth directory (same basename).

```bash
python 03.Eval.py -p pred_dir -t true_dir > result.tsv
```

| Option      | Description |
|-------------|-------------|
| `-p, --pred` | Directory containing predicted GFF files (must exist) |
| `-t, --true` | Directory containing ground truth GFF files (must exist) |

(1) All input files must be in GFF3 format (tab-separated).  
(2) Only lines with feature type CDS (3rd column) are considered.  
(3) The script expects the same file name in both directories for matching.

### Output
A tab-separated table printed to stdout with the following columns:

| Column   | Description |
|----------|-------------|
| Assembly | Base name of the file (without .gff extension) |
| Pred     | Total number of predicted CDS features in the file |
| True     | Total number of reference CDS features in the truth file |
| True_Pos | Number of predicted ORFs that match a reference ORF |

## 04. Benchmarking Running Speed
`04.Test_Speed.py` benchmarks the running time of gene-finding tools (clovers, mga, prodigal) on a set of genomes.

```bash
python 04.Test_Speed.py --target genomes.txt --gbff-dir gbff/ # [other options]
```

| Option         | Description |
|----------------|-------------|
| `--target`     | File with one genome accession per line (required) |
| `--gbff-dir`   | Directory containing `<acc>.gbff` files; may be repeated to search multiple directories (required) |
| `--bin`        | Directory containing the tool executables (default: `bin`) |
| `--output`     | Output CSV path (default: `<cwd>/speed_benchmark.csv`) |
| `--tools`      | Comma-separated tools to benchmark (default: `clovers,mga,prodigal`) |
| `--threads`    | Threads passed to clovers via `-T` (default: 16) |

For each accession, the GenBank file is converted to FASTA in a temporary directory and each tool is timed with `time.perf_counter()`.

### Output
A CSV file with columns `Genome`, `Size_bp`, and `<tool>_sec` (elapsed seconds per tool). Genomes already present in an existing output CSV are skipped, so an interrupted run can be resumed; failed genomes are reported to stdout and the batch continues.

## 05. Generating Decoy Negative-Control Genomes
`05.Neg_Ctrl.py` builds **negative-control genomes** for false-positive testing of gene finders. For each input genome it synthesizes "decoy ORFs" whose sequence is drawn from the genome's own codon usage, and splices them into the inter-ORF (non-coding) gaps. Because the decoys are never real genes, any CDS predicted inside a decoy region is a false positive of the tested tool.

```bash
python 05.Neg_Ctrl.py --gbff-root gbff_root --output-root out_root --groups Arch_Train Bac_Train # [other options]
```

For each GenBank file under `<gbff_root>/<group>/`, the script:

1. Concatenates all records of the file into one sequence and determines the modal CDS `/transl_table` (fallback: 11) as the genetic code;
2. Extracts every ORF ≥ 90 nt on both strands (a stop-to-stop segment containing at least one start codon, partial ORFs at sequence ends ignored);
3. Estimates sense- and stop-codon usage from those ORFs (the genome's codon pool, excluding the terminal stop);
4. Targets `max(20, min(200, round(0.05 × n_orfs)))` decoys per genome and samples decoy lengths from the empirical ORF-length distribution;
5. Finds non-overlapping slots inside the inter-ORF gaps (each decoy keeps a 20-nt flanking margin) and places the decoys longest-first; if the gap capacity is insufficient the decoy count is reduced;
6. Synthesizes each decoy from the codon pool — body codons with no internal stop, start codon ATG/GTG/TTG at 0.80/0.15/0.05, and a stop codon drawn from the genome's stop usage — then splices it into the genome on a random strand and validates that every decoy keeps valid termini and translates stop-free.

| Option         | Description |
|----------------|-------------|
| `--gbff-root`  | Root directory containing the group subdirectories with the input GenBank files (`.gbff` / `.gbff.gz`) (required) |
| `--output-root` | Output root directory (required) |
| `--groups`     | Names of the subdirectories under `--gbff-root` to process (required) |
| `--seed`       | Global random seed (default: 42); deterministic per-genome seeds are derived from it |
| `--workers`    | Number of parallel worker processes (default: 8) |
| `--limit`      | Process at most N genomes per group (default: all) |

### Output
- Under `<output_root>/<group>/`:
  - `<acc>.fa` — the decoy-augmented genome (records concatenated, 70-nt lines);
  - `<acc>.decoy.gff` — GFF3 `CDS` features of the inserted decoys (source `Neg_Ctrl`).
- `<output_root>/manifest_<group>.csv` — per-genome summary with columns `accession`, `group`, `n_records`, `record_lengths`, `merged_len`, `transl_table`, `n_orfs`, `n_decoys_target`, `n_decoys_inserted`.
- `<output_root>/Neg_Ctrl.log` — run log (console + file).

Genomes already present in the manifest with both output files existing are skipped, so an interrupted run can be resumed; failed genomes are logged and do not stop the batch.

## Appendix: Setup of the Zcurve extension
Build the **Cython** extension to accelerate the Z-curve calculation of Python scripts.
The implementation is `Zcurve.pyx` (OpenMP-parallelized; the former hand-written
CPython/C extension `Zcurve.cpp` was replaced by the Cython version).
```bash
cd scripts
pip install -r requirements.txt
python setup.py build_ext --inplace
```
The build requires a C/C++ compiler. The `setup.py` automatically selects the
appropriate flags for the active toolchain: MSVC (`/O2 /openmp /arch:AVX2`) or
GCC/MinGW (`-O3 -mavx -mfma -fopenmp`). After building, the module is importable
in-place from this directory:
```python
import Zcurve
import numpy as np

X = Zcurve.encode(["ATCGATCG", "GCTAGCTA"])   # -> np.ndarray, shape (2, 189), float32
X = Zcurve.encode(sequences, n_jobs=4)        # parallel encoding (0 = all cores)
```

| Package              | Description                         |
|----------------------|-------------------------------------|
| biopython            | Python libraries for bioinformatics |
| scikit-learn         | Machine learning library for Python |
| torch                | PyTorch library for deep learning   |
| numpy                | NumPy (required to build Zcurve)    |
| cython               | Cython compiler (required to build Zcurve) |

`matplotlib` is optional and only used by `01.GC_Partition.py` to draw the GC-distribution plots.
